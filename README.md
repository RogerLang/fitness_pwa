# 练了么（Fitness PWA）

`fitness_pwa` 是一个个人力量训练记录 PWA，用于制定下一次训练、记录每组重量/次数/RIR、查看历史与趋势，并记录体重和围度数据。

应用采用 local-first 设计。训练模板、当前待训练计划、训练历史、身体数据和训练草稿默认保存在当前浏览器 IndexedDB；需要跨设备使用时，可选同步到单独的 Private GitHub repository。

## 主要功能

- 在“计划”页选择训练模板并生成下一次训练建议
- 根据历史记录和目标次数区间生成重量/次数建议
- 手动调整候选计划后推送为当前待训练计划
- 在“训练”页执行已推送计划，记录重量、次数、RIR 和每组完成状态
- 当前训练可临时增加或减少组数，不修改长期模板
- 自动保存未完成的训练草稿，刷新后继续恢复
- 查看训练历史和动作趋势
- 记录体重、胸围、腰围和臂围
- 导入 / 导出本地 JSON 备份
- 可选 Private GitHub 多设备增量同步
- PWA 安装与离线静态资源缓存

## 使用流程

当前训练流程分为三个层级：

```text
训练模板 → 当前待训练计划 → 训练记录
```

1. 在“计划”页选择一个训练模板。
2. 查看系统根据历史生成的建议，并按需要修改本次重量、次数和组数。
3. 点击“推送训练计划”。全局只保留一份当前待训练计划。
4. 进入“训练”页执行这份计划并记录实际训练数据。
5. 保存本次训练后，实际数据进入历史记录；下一次再从模板生成新的候选计划。

模板修改只影响以后生成的新计划。已经推送的当前待训练计划不会因为模板随后被修改而同步变化。

## 部署

项目由原生 HTML、CSS 和 JavaScript 组成，没有构建步骤。推荐直接使用 GitHub Pages：

1. Fork 或复制本仓库。
2. 保留当前目录结构。
3. 在 Pages 设置中选择从 `main` 分支根目录发布。
4. 使用生成的 HTTPS 地址打开应用。

根目录保留 `index.html`、`manifest.webmanifest`、`sw.js` 和 `rescue.html` 等入口文件；样式、图标和 JavaScript 按职责放入子目录。

## 第一次使用

全新浏览器中没有训练模板时，可以通过两种方式初始化：

1. 已有其他设备数据：完成 GitHub 同步配置后点击“从 GitHub 合并”。
2. 已有本地备份：在“设置 → 本地备份”中导入 `fitness-backup-*.json`。

模板加载后，到“计划”页生成并推送下一次训练，再到“训练”页执行。

## Private GitHub 同步配置

建议单独创建一个 Private repository 作为训练数据仓库，例如 `fitness-data-private`。为该数据仓库创建 Fine-grained personal access token，并仅授予同步所需的仓库内容读写权限。

在“设置 → GitHub 同步”中填写：

- GitHub 用户名
- Private 仓库名
- Fine-grained token

点击“保存本机同步信息”后，配置保存在当前浏览器。应用会在同步前检查目标仓库必须为 Private repository。

如果当前设备已有完整数据，第一次点击“增量同步”会创建远端数据结构；新设备第一次使用时点击“从 GitHub 合并”。

## 多设备使用

推荐顺序：

1. 切换设备后先从 GitHub 合并最新数据。
2. 在“计划”页确认当前待训练计划是否正确。
3. 正常训练并保存记录。
4. 训练完成后执行增量同步。
5. 下一台设备使用前再次拉取。

训练记录和身体记录按条目合并。训练模板和当前待训练计划跟随 `plans.json` 使用 revision 检测多设备修改冲突，发生冲突时应用会阻止静默覆盖。

## 本地备份

“设置 → 本地备份”支持导出明文 JSON、导入备份以及清理当前设备训练数据。同步凭据不会进入导出的训练备份。

修改训练模板、迁移设备或调整同步配置前，可以先导出一份备份。

## PWA 与缓存恢复

在支持 PWA 的浏览器中，可通过页面安装按钮或浏览器菜单添加到桌面/主屏幕。Service Worker 会缓存应用静态资源，GitHub 同步仍需要网络连接。

发布后若遇到旧缓存导致的启动异常，可访问：

```text
rescue.html
```

该页面只清理 Service Worker 和静态缓存，不删除 IndexedDB 中的训练数据。
